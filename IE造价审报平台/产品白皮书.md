## 一、品牌释义

### IE = Intelligent Engineering

**Intelligent（智能）**

平台以智能为核心驱动力，将传统造价评审中繁琐的人工操作转化为自动化流程：

- **智能解析**：自动识别 Excel 多级表头结构，精准定位"审核增减-金额"列，无需人工指定数据位置
- **智能分类**：根据调整金额的正负值，自动判别"审增"与"审减"，无需人工标注
- **智能清理**：自动检测无数据的工程类型区段并从报告中移除，确保输出洁净专业
- **智能填充**：以锚点定位技术将数据精准注入 Word 模板，替换全部占位符

**Engineering（工程）**

平台深耕建设工程造价领域，覆盖七大工程类型：

### 品味之选

选择 IE，是选择一种对专业品质的执着追求。

**品味，在于对格式的苛求。** 平台生成的评审报告严格遵循政府红头文件规范——48pt 红色 Times New Roman 文头、18pt 黑体居中标题、14pt 仿宋正文、红色双线分隔（上细下粗），每一个字号、每一种字体、每一条线宽都经过精心校准，确保输出的文档可直接用于正式呈报，无需二次排版。

**品味，在于对细节的洞察。** 多级表头识别算法采用通用结构推断，精准区分组表头、子组标题与叶子单元格——无论子组标题命名为"审核增减"还是"差异明细"，都能正确排除；并通过 `data_start_row` 边界控制避免数据行被误读为表头，找到隐藏在层层表头之下的"审核增减-金额"列。单位识别引擎按照 m² → m³ → m 的优先级匹配，避免"混凝土"等通用词汇的误分类；空单位智能显示为"元"而非"元/"，每一个细节都经过推敲。

**品味，在于对完整的坚守。** 不仅仅满足于生成报告——版本管理记录每次修改、审核流程留下完整轨迹、数据备份守护每一份资产、操作日志追溯每一次行为、数据字典规范每一条术语。55 个 API 端点，覆盖从项目创建到报告归档的全生命周期。

**品味，在于对体验的打磨。** 一站式工作台设计，从项目创建、Excel 上传、报告生成到审核下载，全部在首页完成，无需在多个页面间跳转。单文件 exe 部署，双击即用，零配置开箱即行。

## 二、产品概述

### 定位

IE 造价审报平台是一款面向工程造价咨询企业、建设单位、审计部门的**自动化造价评审报告生成系统**。它将 Excel 清单数据与 Word 报告模板相结合，通过智能解析与自动填充技术，一键生成符合政府公文规范的工程造价评审报告。

### 核心价值

| 痛点 | 解决方案 | 价值 |
|------|----------|------|
| 手工填写报告耗时数小时 | 自动解析 Excel + 模板填充 | 30 秒生成完整报告 |
| 审增/审减分类易出错 | 根据金额正负自动判别 | 零分类错误 |
| 报告格式不符合公文规范 | 内置红头文件模板 | 直接用于正式呈报 |
| 多人协作版本混乱 | 报告版本管理 + 审核流程 | 完整版本追溯 |
| 数据安全无保障 | 数据备份恢复 + 操作日志 | 全链路安全审计 |

## 三、功能详述

### 3.1 用户认证与权限

- **用户注册**：新用户可通过注册页面自助创建账号（用户名、密码、显示名称）
- **用户登录**：JWT 令牌认证，登录后自动获取用户角色信息
- **角色权限**：管理员（admin）可访问系统管理功能；普通用户仅可使用业务功能
- **路由守卫**：前端路由级权限控制，系统管理页面仅管理员可见
- **操作日志**：登录、注册、创建项目、上传 Excel、生成报告等操作均记录日志

### 3.2 项目管理

- **项目 CRUD**：创建、查看、编辑、删除项目，删除时同步清理物理文件
- **一站式工作台**：所有操作（项目创建、数据上传、报告生成）在工作台首页完成
- **数据汇总**：自动统计各工程类型的送审金额、审定金额、审增/审减金额
- **数据导出**：支持导出项目 Excel 数据
- **数据校验**：一键校验数据完整性

### 3.3 Excel 数据导入

- **多级表头识别**：通用结构推断算法，自动区分组表头（送审工程/审结工程/审计结果）、子组标题（审核增减/金额（元））与叶子单元格（工程量/综合单价/合价/金额）
- **子组标题智能排除**：中间行单元格仅在同行下方有更细分的叶子时才被识别为子组标题，避免误排除"工程量"等本身就是叶子的单元格
- **数据行边界控制**：通过 `data_start_row` 限定表头读取范围，避免数据行（如"土方工程"分组标题）被误读为表头层
- **字段自动映射**：自动识别送审数量/单价/合价、审定数量/单价/合价、调整金额
- **adjustment 列优先级识别**：四遍扫描策略，优先匹配特定别名（审增金额/审减金额），再回退通用"金额"，避免通用词抢先
- **审增/审减自动判别**：根据调整金额正负值自动分类（正数=审增，负数=审减）
- **单文件上传**：单个 Excel 可包含多个 Sheet，覆盖全部 7 类工程
- **数据回滚保护**：新数据解析成功后才删除旧数据，失败时回滚，保障数据安全
- **内存优化**：使用 read_only 模式读取 Excel，try/finally 确保资源释放

### 3.4 模板管理

- **模板上传**：支持上传 .docx 格式的报告模板
- **模板预览**：在线查看模板内容（显示占位符）
- **变量扫描**：自动扫描模板中的 `{{变量名}}` 占位符
- **变量映射配置**：可配置变量到数据源的映射关系
- **通用模板**：内置标准红头文件模板，含 7 类工程区段

### 3.5 报告生成

- **一键生成**：选择项目和模板，点击"生成报告"即可输出完整 .docx 文件
- **智能填充**：锚点定位技术，以"核增具体情况如下"为锚点，精准插入数据
- **分区结构**：每个工程类型独立包含"核减具体情况"和"核增具体情况"子区段
- **空区段清理**：无数据的工程类型区段自动移除，无空标题残留
- **占位符替换**：项目名称、建设单位、报告编号、送审金额、审定金额、审减金额、核减率、编制日期等全部替换
- **报告预览**：在线预览报告文本内容
- **PDF 导出**：一键导出 PDF 格式

### 3.6 报告版本管理

- **版本创建**：基于当前报告创建新版本（复制 docx 文件）
- **版本列表**：查看报告的所有历史版本
- **版本对比**：基于 difflib 对比两个版本的段落差异
- **版本下载**：下载任意历史版本

### 3.7 报告审核

- **审核状态**：草稿 → 审核中 → 已通过/已驳回
- **审核意见**：支持填写文字审核意见
- **审核历史**：查看上次审核的状态、时间、意见
- **审核日志**：所有审核操作记录在操作日志中

### 3.8 数据备份与恢复

- **手动备份**：管理员可随时创建数据备份（数据库 + 上传文件）
- **备份列表**：查看所有备份记录
- **一键恢复**：选择备份点一键恢复数据
- **备份删除**：清理过期的备份文件
- **时间戳归档**：备份文件按时间戳归档至 data/backups/

### 3.9 数据字典

- **预置数据**：初始化 20 条默认数据（7 工程类型、9 计量单位、4 项目状态）
- **分类管理**：按分类标签切换查看
- **CRUD 操作**：增删改查字典项
- **分类列表**：获取所有字典分类

### 3.10 系统设置

- **公司名称**：配置报告中的公司名称
- **报告标题前缀**：自定义报告标题
- **上传限制**：配置最大上传文件大小
- **工程类型**：配置支持的工程类型列表

### 3.11 操作日志

- **完整记录**：登录、注册、项目创建、Excel 上传、报告生成、审核等操作
- **管理员可见**：仅管理员可查看操作日志
- **分页查询**：支持分页浏览日志记录

### 3.12 系统运行监控

- **系统托盘图标**：exe 运行时显示蓝色"IE"托盘图标，提供"打开浏览器"和"退出服务"操作
- **服务健康检测**：前端每 3 秒轮询 `/api/health` 端点，连续 2 次失败（约 6 秒）后显示全屏遮罩
- **退出联动提示**：托盘"退出服务"后，前端检测到服务停止，显示"服务已停止"遮罩并提供"关闭页面"按钮
- **登录页豁免**：未登录状态下不发起健康检测，避免无意义请求

## 五、部署与使用

### 方式一：exe 直接部署（推荐）

1. 将 `dist/IE造价审报平台.exe` 复制到任意目录
2. 双击运行，自动创建数据目录结构：
   ```
   IE造价审报平台.exe
   data/           ← 数据库（自动创建）
   uploads/        ← 上传文件（自动创建）
   logs/           ← 日志文件（自动创建）
   ```
3. 浏览器自动打开 `http://localhost:8000`
4. 使用默认账号登录：**admin / admin123**

### 方式二：开发模式部署

```bash
# 1. 创建虚拟环境
python -m venv ..\venv
..\venv\Scripts\activate

# 2. 安装后端依赖
pip install -r requirements.txt

# 3. 安装前端依赖
cd frontend
npm install

# 4. 启动后端（新终端）
cd backend
python main.py

# 5. 启动前端（新终端）
cd frontend
npm run dev
```

访问 `http://localhost:5173`（前端）或 `http://localhost:8000`（后端）

### 重新打包 exe

```bash
# 确保前端已构建
cd frontend && npm run build && cd ..

# 使用全局 Python（需已安装 PyInstaller）
python build_exe.py
```

### 安全设计

- JWT 令牌认证，全部端点需登录
- 管理员权限校验（系统设置、备份、日志）
- 密码 bcrypt 哈希存储
- SQL 注入防护（SQLAlchemy ORM 参数化查询）
- 文件名安全处理（仅过滤路径分隔符和控制字符）
- 上传文件大小限制（默认 10MB）
- SECRET_KEY 等敏感参数通过环境变量配置
- 全局异常处理保留 HTTP 状态码

### 性能优化

- SQLite WAL 模式，支持并发读写
- 系统设置内存缓存
- 前端文件路径 LRU 缓存（256 条）
- Excel 只读模式解析，内存占用低
- GZip 压缩响应（>1KB）
- 前端代码分割与 gzip 静态资源
