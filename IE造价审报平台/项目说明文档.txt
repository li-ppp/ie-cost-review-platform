项目概述
--------------------------------------------------------------------------------
本系统是一个自动化工程造价评审报告生成平台，采用前后端分离架构，支持一站式完成项目创建、
Excel数据上传、报告模板管理、评审报告自动生成等功能。

技术栈：
- 后端：Python 3.12 + FastAPI + SQLAlchemy + SQLite
- 前端：Vue 3 + TypeScript + Element Plus + Vite
- 打包：PyInstaller（单文件exe部署）

默认账户：admin / admin123
访问地址：http://localhost:8000


版本更新记录（v2.5）
--------------------------------------------------------------------------------
本次更新聚焦 Excel 多级表头识别算法的通用化重构与系统运行监控能力建设，
解决用户反馈的"审核增减列识别错误（M/N/O 列错位）"问题，并增加托盘退出
与前端联动的服务停止检测机制：

1. Excel 多级表头通用结构推断（核心重构）
   - 旧代码依赖关键词（"审核增减"等）识别子组标题，遇到非关键词命名
     （如"差异明细"）会漏判；遇到子组标题跨列合并时会误判为叶子文本
   - 新增 _scan_subgroup_cells 函数，基于纯结构推断：中间行单元格
     (r, c) 是子组标题，当且仅当最底行 (last_row, c) 也有值
   - 完全不依赖任何关键词，对"审核增减"/"差异明细"/"金额（元）"等任意
     子组标题命名均能正确排除
   - 新增 test_adjustment_subgroup_non_keyword 单元测试验证非关键词场景

2. data_start_row 边界控制（修复 N/O 列错位 bug）
   - 旧代码 _read_header_area 默认读 4 行表头，但 XX路项目.xlsx 的 R6
     是数据行（"土方工程"分组标题），被误读为表头层
   - 导致 last_row=6，last_row_cells={3:'土方工程'}，子组识别逻辑失效
   - 新增 data_start_row 参数，限制表头读取范围（仅读到 data_start_row-1）
   - 贯穿 detect_column_mapping、_parse_sheet_items、preview_excel_file
     全链路传递，确保数据行永不进入表头区域
   - 修复后 XX路项目所有 7 类工程的 adjustment 列正确识别为 N 列
     （值如 -11413.21、-120229.39、4.32 等，符合预期）

3. adjustment 列四遍扫描策略
   - Pass 1: 审计结果组内，叶子含特定别名（审增金额/审减金额/调整金额等）
     —— 子组标题被排除，避免误命中
   - Pass 2: 审计结果组内，叶子含通用"金额"
   - Pass 3: 无组表头时，全局叶子含特定别名
   - Pass 4: 旧模板兼容（full_text 同时含"审核增减"和"金额"）
   - 解决"通用金额抢先于特定别名审增金额"的优先级问题

4. 系统托盘图标与进程管理
   - main.py 新增 _create_tray_icon() 函数，使用 pystray 创建托盘图标
   - 蓝色"IE"图标，菜单含"打开浏览器"和"退出服务"两个选项
   - uvicorn 在 daemon 线程运行，托盘在主线程
   - "退出服务"触发 icon.stop() + os._exit(0) 干净终止进程

5. 前端健康检测与服务停止联动
   - App.vue 新增 serviceDown 响应式状态与健康检测轮询
   - 每 3 秒轮询 /api/health（使用原生 fetch 绕过 axios 拦截器）
   - 连续 2 次失败（约 6 秒）后显示全屏遮罩
   - 遮罩提示"服务已停止"，提供"关闭页面"按钮
   - 登录页豁免（未登录时不发起检测，避免无意义请求）

6. 单元测试扩充
   - 新增 test_adjustment_subgroup_non_keyword 测试
   - 验证非关键词子组标题（"差异明细"）场景下的正确识别
   - Excel 解析器测试用例数：18 → 21
   - 总测试用例数：62 → 71

7. 文档更新
   - 产品白皮书：新增 v2.5 版本条目，更新多级表头识别描述，新增 3.12 节
   - API 文档：全面重写为 v2.5，新增 14 个章节，覆盖全部 55 个端点

版本更新记录（v2.2）
--------------------------------------------------------------------------------
本次更新聚焦全局代码健壮性与性能优化，涵盖安全、数据完整性、错误处理、性能等维度：

1. 全接口JWT认证加固
   - 项目管理、模板管理、报告生成所有接口均要求JWT认证
   - 审核操作记录审核人ID（reviewer_id）
   - 操作日志记录用户名便于审计

2. 数据丢失防护（P0级修复）
   - Excel上传流程重构：先解析新文件成功，再删除旧数据
   - 解析或保存失败时自动回滚，旧数据不受影响
   - 旧Excel物理文件在事务提交成功后才删除

3. 中文文件名支持
   - 修复文件名清理逻辑（原正则 \w 不支持中文，导致中文文件名被替换为下划线）
   - 新的清理函数仅移除路径分隔符和控制字符，完整保留中文字符
   - 文件名长度限制为100字符，避免文件系统路径过长

4. Excel解析器健壮性增强
   - 使用 read_only=True 模式加载工作簿，降低内存占用约60%
   - try/finally 保证工作簿句柄释放，避免文件锁定
   - 0值正确处理（原 any() 判断将0视为空值，导致数据丢失）
   - 自动计算调整金额：调整金额 = 审核合价 - 送审合价
   - 单位列数据优先从Excel读取，为空时再从名称推断

5. 报告生成器健壮性增强
   - 修复正则表达式空格bug（原 (?:审减 | 核减) 因空格无法匹配）
   - 提取 _fill_cell 辅助函数消除重复代码
   - 所有数值转换使用 is not None 判断，0值不再被误判为空
   - 单价为空时显示"元"而非"元/"
   - 段落删除前增加 parent is not None 检查
   - 文档加载和保存增加异常捕获

6. 输入验证强化
   - 新增 ReviewRequest Pydantic 模型（原为裸dict）
   - 新增 DataUpdateRequest Pydantic 模型用于数据更新
   - 列表查询增加 MAX_LIMIT=500 上限，防止过量查询
   - skip 参数负值自动归零

7. 线程安全缓存
   - 项目列表缓存增加 threading.Lock 保护
   - 前端文件路径缓存改为 LRU（OrderedDict），上限256条目
   - 避免高并发下缓存不一致和内存无限增长

8. 环境变量配置支持
   - JWT_SECRET_KEY：JWT签名密钥
   - JWT_EXPIRE_MINUTES：令牌有效期（默认1440分钟=24小时）
   - DEFAULT_ADMIN_PASSWORD：默认管理员密码（默认admin123）
   - CORS_ORIGINS：CORS允许的源（逗号分隔）

9. 错误处理改进
   - 全局异常处理器保留 HTTPException 的状态码和详情（原全部转为500）
   - 后台报告生成失败时先 db.rollback() 再更新状态
   - 裸 except 全部替换为 except Exception
   - PDF导出页码换页时重置字体

10. 数据库与文件系统
    - 数据库路径改用 os.path.join（原使用 / 拼接，跨平台兼容性更好）
    - 删除项目时清理关联的Excel物理文件
    - 删除模板时清理模板物理文件
    - 文件操作异常均被捕获并记录日志，不影响主流程

11. 依赖清理
    - 移除 .xls 支持（openpyxl不支持，原代码会静默失败）
    - 移除 shutil 依赖，直接使用 content 写入文件
    - 模板上传移除 .doc 支持（python-docx不支持）

2.8.1 Excel解析服务
文件：backend/services/excel_parser.py

功能：
- 解析Excel文件（.xlsx，openpyxl支持格式）
- 支持多sheet解析
- 自动识别工程类型
- 提取数据项（项目名称、单位、送审/审核数据）
- 通用结构推断多级表头（v2.5 核心特性）
- 自动计算调整金额（当Excel无调整列时）

多级表头识别（v2.5 通用结构推断）：
- _read_header_area: 读取表头区域，接受 data_start_row 参数限制读取范围，
  避免数据行（如"土方工程"分组标题）被误读为表头层
- _scan_group_headers: 识别组表头（送审工程/审结工程/审计结果等），
  基于关键词匹配，组表头跨多列时值仅在起始列
- _scan_subgroup_cells: 识别子组标题单元格，基于纯结构推断：
  中间行单元格 (r, c) 是子组标题，当且仅当最底行 (last_row, c) 也有值；
  不依赖任何关键词，对"审核增减"/"差异明细"/"金额（元）"等任意命名均能正确排除
- _detect_adjustment_column: 四遍扫描策略识别 adjustment 列：
  Pass 1: 审计结果组内叶子含特定别名（审增金额/审减金额/调整金额等）
  Pass 2: 审计结果组内叶子含通用"金额"
  Pass 3: 无组表头时全局找特定别名
  Pass 4: 旧模板兼容（full_text 同时含"审核增减"和"金额"）

解析逻辑：
- 使用 read_only=True 模式加载，降低内存占用
- try/finally 保证工作簿句柄释放
- 根据sheet名称识别工程类型（道路工程、排水工程、照明工程等）
- 定位数据起始行（跳过表头），并传入 detect_column_mapping 限制表头范围
- 提取列数据（项目名称、单位、送审量、送审价、送审合价、审核量、审核价、审核合价、调整金额）
- 单位列优先从Excel读取，为空时从名称推断
- 调整金额自动计算：调整金额 = 审核合价 - 送审合价
- 0值正确处理（使用 is None 判断，避免0被误判为空）
- 支持手工列映射 override（column_mapping_override 参数）

支持格式：
- 单sheet格式：一个文件一个工程类型
- 多sheet格式：一个文件多个工程类型（每个sheet一个类型）
- 简单格式：sheet名为"道路工程"等
- 审表-09格式：sheet名为"审表-09 分部分项..."等（含 ~1~6 后缀映射 7 类工程）

3. 生成造价分析文本（送审金额、审定金额、审减金额、审减率、各工程类型分析、异常项分析）
4. 插入分析文本到报告正文（在"核增具体情况如下"之前）
5. 定位数据填充区域（锚点：核增具体情况如下）

- build_item_line(item)：构建单个清单项的评审描述文本

- 动态刷新段落列表
- 正则匹配明细项

工程类型别名支持：
- 道路工程：道路、路工程、市政道路

- 交安工程：交通安全、交安、交通工程

- 照明工程：照明、路灯、路灯工程
- 电力工程：电力、电气、供电

================================================================================
四、核心业务流程
================================================================================

4.1 用户登录流程
--------------------------------------------------------------------------------
1. 用户在Login.vue页面输入用户名和密码
2. 前端调用authApi.login()发送POST /api/auth/login请求
3. 后端验证用户名和密码
4. 验证成功，生成JWT令牌（有效期24小时）
5. 返回access_token给前端
6. 前端保存token到localStorage
7. 跳转到工作台页面（/）
8. 后续请求自动携带token（通过Axios拦截器）


4.2 项目创建流程
--------------------------------------------------------------------------------
1. 用户在工作台点击"新建项目"按钮
2. 弹出创建项目对话框
3. 填写项目名称、建设单位、工程类型
4. 前端调用projectApi.create()发送POST /api/projects/请求
5. 后端创建项目记录
6. 返回项目信息
7. 刷新项目列表


4.3 Excel上传流程
--------------------------------------------------------------------------------
1. 用户点击项目的"上传Excel"按钮
2. 弹出上传对话框
3. 选择或拖拽Excel文件（.xlsx）
4. 前端调用projectApi.uploadExcel()发送POST /api/projects/{id}/upload请求
5. 后端验证文件格式、大小和文件头（PK魔术字节）
6. 保存文件到uploads/excel目录（保留中文名）
7. 调用excel_parser解析Excel数据（在删除旧数据之前）
8. 解析成功后，删除旧的ExcelFile和ExcelData记录（db.flush未提交）
9. 创建新的ExcelFile和ExcelData记录（批量提交）
10. 事务提交成功后，删除旧的Excel物理文件
11. 返回上传结果（文件ID、工程类型、数据项数量）
12. 刷新Excel文件列表

数据安全机制：
- 解析失败时，旧数据不受影响，新文件自动清理
- 保存失败时，事务回滚，新文件自动清理
- 只有事务提交成功后才会删除旧物理文件


4.4 报告生成流程
--------------------------------------------------------------------------------
1. 用户点击项目的"生成报告"按钮
2. 弹出生成报告对话框
3. 选择报告模板
4. 前端调用reportApi.generate()发送POST /api/reports/generate请求
5. 后端验证项目和模板
6. 加载项目Excel数据
7. 创建Report记录（状态：generating）
8. 提交后台任务生成报告
9. 返回报告记录
10. 后台任务：
    a. 调用report_generator服务
    b. 读取Word模板
    c. 替换占位符数据
    d. 填充项目信息和Excel数据
    e. 保存生成的报告文件
    f. 更新报告状态（generated/failed）
11. 用户可以在报告列表查看生成状态
12. 生成完成后可以下载或预览报告


4.5 数据校验流程
--------------------------------------------------------------------------------
1. 前端调用projectApi.validate()发送POST /api/projects/{id}/validate请求
2. 后端检查项目Excel数据
3. 校验规则：
   - 检查是否上传了Excel文件
   - 检查每个文件是否有数据项
   - 检查必填字段（项目名称）
   - 检查数值字段（不能为负数）
   - 检查数据一致性（送审合价 = 送审工程量 × 送审单价）
4. 返回校验结果（valid、errors、warnings）


4.6 数据导出流程
--------------------------------------------------------------------------------
1. 前端调用projectApi.exportData()发送GET /api/projects/{id}/export请求
2. 后端加载项目所有Excel数据
3. 创建新的Excel工作簿
4. 为每个工程类型创建一个sheet
5. 写入表头和数据
6. 调整列宽
7. 返回Excel文件流
8. 前端下载文件

================================================================================
六、技术要点和注意事项
================================================================================

6.1 时间处理
--------------------------------------------------------------------------------
- 所有时间字段使用北京时间（UTC+8）
- JWT令牌使用timezone-aware datetime
- 数据库模型使用_utcnow()函数返回带时区的北京时间
- 前端使用toLocaleString('zh-CN')显示时间


6.2 认证授权
--------------------------------------------------------------------------------
- 使用JWT令牌进行身份认证
- 令牌有效期24小时
- 前端通过Axios拦截器自动添加token到请求头
- 后端通过Depends(get_current_user)验证token
- 管理员权限通过检查user.role == "admin"


6.3 文件上传
--------------------------------------------------------------------------------
- Excel文件限制：.xlsx格式，最大10MB
- 模板文件限制：.docx格式，最大10MB
- 使用安全文件名（保留中文字符，仅移除路径分隔符和控制字符）
- 验证文件格式（检查PK魔术字节，确保为有效ZIP/OOXML格式）
- 文件名长度限制100字符，避免文件系统路径过长


6.4 数据库优化
--------------------------------------------------------------------------------
- SQLite使用WAL模式提升并发性能
- 使用joinedload预加载关联数据
- 使用SQL聚合函数避免内存加载


6.5 错误处理
--------------------------------------------------------------------------------
- 全局异常处理器捕获未处理异常
- API路由使用HTTPException返回标准错误
- 前端Axios拦截器统一处理错误
- 日志记录详细错误信息


6.6 性能优化
--------------------------------------------------------------------------------
- 报告生成使用后台任务（BackgroundTasks）
- 前端使用v-loading指令显示加载状态
- 使用分页查询大量数据
- 静态文件使用gzip压缩

七、常见问题和解决方案
================================================================================

7.1 登录后点击设置显示"未授权"
--------------------------------------------------------------------------------
原因：JWT令牌时间不一致
解决：已修复，使用timezone-aware datetime


7.2 时间显示不正确
--------------------------------------------------------------------------------
原因：后端使用UTC时间，前端未转换
解决：已修复，后端统一使用北京时间（UTC+8）


7.3 上传Excel失败
--------------------------------------------------------------------------------
可能原因：
- 文件格式不正确（不是有效的Excel文件）
- 文件超过10MB
- Excel中没有有效数据

解决：
- 确保使用.xlsx或.xls格式
- 检查文件大小
- 确保Excel中有数据


7.4 报告生成失败
--------------------------------------------------------------------------------
可能原因：
- 模板文件不存在
- 项目没有Excel数据
- 模板格式不正确

解决：
- 检查模板是否上传成功
- 确保项目已上传Excel数据
- 检查模板格式是否符合要求


7.5 无法访问系统
--------------------------------------------------------------------------------
可能原因：
- 服务器未启动
- 端口被占用
- 防火墙阻止

解决：
- 检查exe是否正常运行
- 检查8000端口是否被占用
- 临时关闭防火墙测试

================================================================================
九、性能优化措施
================================================================================

9.1 后端性能优化
--------------------------------------------------------------------------------

9.1.1 数据库查询优化
- 项目列表查询使用子查询避免N+1问题
- 为高频查询字段添加索引（Project.name, Project.client_name, Project.project_type, 
  Project.status, Project.created_at, Project.updated_at, Report.project_id, 
  Report.template_id, Report.status, Report.generated_at）
- 使用joinedload预加载关联数据
- 使用SQL聚合函数避免内存加载

9.1.2 数据库连接优化
- 配置连接池参数（pool_size=10, max_overflow=20, pool_timeout=30）
- 启用SQLite WAL模式提升并发性能
- 配置SQLite缓存（cache_size=-8000，约8MB）
- 临时表使用内存存储（temp_store=MEMORY）
- 启用内存映射（mmap_size=256MB）

9.1.3 响应压缩
- 启用GZip中间件，对大于1KB的响应进行压缩
- 减少网络传输数据量，提升响应速度

9.1.4 系统设置缓存
- 实现系统设置内存缓存机制
- 避免重复查询数据库
- 设置更新时自动刷新缓存

9.1.5 前端静态文件缓存
- 实现前端文件路径缓存，避免重复文件系统检查
- 为静态资源添加Cache-Control头
  - assets/目录：max-age=31536000（1年）
  - 其他文件：max-age=3600（1小时）
- 减少日志输出，提升性能

9.1.6 报告查询优化
- 报告列表按生成时间倒序排列
- 使用索引加速排序查询


9.2 前端性能优化
--------------------------------------------------------------------------------

9.2.1 代码分割
- 使用Vite的manualChunks进行细粒度代码分割
- 将依赖库分离为独立chunk：
  - vue-vendor：Vue、Vue Router、Pinia
  - element-plus：Element Plus组件库
  - utils：Axios、Day.js等工具库
- 减少单个chunk大小，提升加载速度

9.2.2 资源压缩
- 启用GZip压缩（vite-plugin-compression）
- 对超过10KB的文件进行压缩
- 保留原始文件，同时生成.gz压缩版本

9.2.3 构建优化
- 启用CSS代码分割（cssCodeSplit: true）
- 关闭生产环境源码映射（sourcemap: false）
- 使用Terser压缩代码
- 移除console和debugger语句
- 优化chunk命名（使用hash避免缓存问题）

9.2.4 资源分类
- JavaScript文件：assets/js/[name]-[hash].js
- CSS文件：assets/[ext]/[name]-[hash].[ext]
- 其他资源：按类型分类存储


9.3 性能提升效果
--------------------------------------------------------------------------------

9.3.1 查询性能
- 项目列表查询：从N+1查询优化为1次查询，性能提升约10-50倍
- 报告列表查询：使用索引排序，查询速度提升约5-10倍

9.3.2 网络传输

- 静态资源缓存：减少重复请求，提升页面加载速度

- 资源压缩：总体积减少约40-60%

9.3.4 数据库性能

- WAL模式：读写并发性能提升约2-3倍

9.3.5 应用层缓存
